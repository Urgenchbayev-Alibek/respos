# ADR-0009. .NET 8 сейчас, переход на .NET 10 LTS

**Статус:** Accepted, follow-up обязателен
**Дата:** 2026-11-10

## Контекст

ТЗ §10.1: «актуальная стабильная LTS .NET», без preview-пакетов. На машине разработки есть .NET 8 и 9 SDK,
.NET 10 SDK не установлен. **Поддержка .NET 8 заканчивается 2026-11-10 — сегодня.** .NET 10 — текущий LTS
(выпущен в ноябре 2025). .NET 9 — STS, не LTS.

## Решение

- Старт на `net8.0` + EF Core 8 + Npgsql 8, чтобы не блокировать работу (SDK есть локально и в CI через
  `actions/setup-dotnet` 8.0.x).
- **Follow-up (User-Todo T1):** после установки .NET 10 SDK — `TargetFramework` → `net10.0`, обновить пакеты
  (ASP.NET Core / EF Core / Npgsql / тестовые), CI → `dotnet-version: 10.0.x`, Docker-образы
  → `mcr.microsoft.com/dotnet/aspnet:10.0` и `sdk:10.0`. Оценка ≈ 1 час + регресс-тесты.
- Не использовать API, устаревшие/удалённые в .NET 10; версии пакетов фиксировать централизованно
  (`Directory.Packages.props`), чтобы апгрейд был одним изменением.
- В production на .NET 8 не выпускать (нет патчей безопасности после EOL).

## Альтернативы

- **Сразу .NET 10** — правильнее, но SDK не установлен; ожидание блокирует команду.
- **.NET 9 (STS)** — тоже короткая поддержка, не LTS.

## Последствия

- Временный технический долг с явной датой; апгрейд — блокер перед пилотом/деплоем.
- При апгрейде проверить breaking changes EF Core 10 / Npgsql по официальным release notes.
