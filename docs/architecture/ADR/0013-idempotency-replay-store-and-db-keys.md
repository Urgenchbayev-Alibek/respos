# ADR-0013. Idempotency: HTTP replay store + DB unique keys

**Статус:** Accepted (реализовано; DECISIONS_v1_1 §8)
**Дата:** 2026-11-10

## Контекст

Критические команды (`POST /payments`, `POST /payments/{id}/refunds`, `POST /orders/{id}/send-to-kitchen`,
`POST /purchases/{id}/receive`) повторяются при сетевых сбоях и двойных кликах. Повтор не должен создавать второй платёж,
второй тикет или второе поступление, а клиент должен получить тот же ответ.

## Решение

Два независимых уровня:

1. **HTTP replay store** — фильтр `[RequireIdempotencyKey]` + `IdempotencyService`, таблица `idempotency_records`,
   UK `(key, user_id)`:
   - заголовок `Idempotency-Key` (UUID) обязателен, иначе `400 idempotency.key_required`;
   - первая обработка: запись «в процессе» с хешем тела → выполнение → сохранение 2xx-ответа (статус + тело);
   - повтор тем же пользователем с тем же телом → сохранённый ответ + заголовок `Idempotent-Replayed: true`;
   - тот же ключ, другое тело → `422 idempotency.key_reused`; параллельный дубль → `409 idempotency.in_progress`;
   - срок хранения 24 ч; просроченная запись удаляется при следующем обращении с тем же ключом (фоновой очистки нет).
2. **DB safety net** — уникальные ключи в данных:
   - `payments (organization_id, idempotency_key)` → `409 payment.duplicate` (например, тот же ключ у другого пользователя);
   - `inventory_consumptions.order_id` — повторное событие оплаты не списывает ингредиенты повторно (ADR-0006);
   - бизнес-инварианты (`amount ≤ remainingAmount`, приёмка ≤ остатка строки) дополнительно отсекают дубли.

## Альтернативы

- Только HTTP-уровень — запись ответа идёт после commit отдельным statement; сбой между ними оставил бы окно для дубля.
- Только DB-ключи — нет повтора исходного ответа, клиенту пришлось бы разбирать 409.
- Распределённый кеш (Redis) — лишняя инфраструктура для одного инстанса MVP.

## Последствия

- Повторы безопасны и прозрачны для UI (тот же ответ).
- Область уникальности различается (пользователь vs организация) — поведение описано в BR-10.5/BR-18.
- При росте объёма понадобится фоновая очистка `idempotency_records`.
