# Accessibility

Цель — **WCAG 2.2 уровень AA** для всех рабочих пространств и лендинга. Проверка: axe (в тестах компонентов
или через браузерное расширение), ручная проверка клавиатурой, Lighthouse для лендинга.

## 1. Язык и семантика

- `<html lang="ru">` или `lang="uz"` (узбекская латиница; при необходимости `uz-Latn`) — меняется вместе
  с языком интерфейса. Фрагменты на другом языке (названия блюд `NameUz` в RU-интерфейсе) — `lang` на элементе.
- Нативные элементы: `<button>` для действий, `<a>` для навигации, `<table>` с `<th scope>` для DataTable,
  landmarks `header/nav/main`. Один `<h1>` на страницу (заголовок экрана).
- Иконочные кнопки — `aria-label` (из i18n). Декоративные иконки — `aria-hidden="true"`.

## 2. Контраст

| Пара | Контраст (расчёт) | Вывод |
|---|---|---|
| `#0F172A` на `#FFFFFF` / `#F8FAFC` | ≈ 17:1 | OK |
| `#475569` (muted) на `#FFFFFF` | ≈ 7.6:1 | OK для любого текста |
| `#F8FAFC` на KDS `#111A2E` | ≈ 16:1 | OK |
| Белый на `#E85D2A` (primary) | **≈ 3.5:1** | Только **крупный текст** (≥ 24px обычный или ≥ 18.66px / 14pt bold) и UI-компоненты (≥ 3:1) |
| Белый на `#CF4D1D` (primary-hover) | ≈ 4.4:1 | Чуть ниже 4.5:1 — тоже только крупный текст |
| `#E85D2A` текстом на белом | ≈ 3.5:1 | Не использовать для обычного текста и ссылок |
| `#D97706` (warning) на белом | ≈ 3.2:1 | Не использовать как цвет текста |
| `#16A34A` (success) на белом | ≈ 3.3:1 | Не использовать как цвет текста |
| `#2563EB` (info) на белом | ≈ 5.2:1 | OK для ссылок |
| `#DC2626` (danger) на белом | ≈ 4.8:1 | OK для текста ошибок |

Значения рассчитаны вручную по формуле WCAG — **перепроверить инструментом** при реализации.

Правила, вытекающие из таблицы:
- Primary-кнопки: белый текст **600–700, ≥ 16px**; в waiter/cashier/KDS кнопки `lg/xl` с текстом ≥ 18–20px bold
  проходят как крупный текст. Для компактных admin-кнопок 14px белый на `#E85D2A` **не проходит AA** —
  открытое решение для команды: (а) все primary-кнопки делать с текстом ≥ 18.66px bold (крупный текст);
  (б) добавить токен `--color-primary-strong` (например `#B4400F`, ≈ 5.7:1) для фона маленьких кнопок и
  текстовых ссылок в primary-тоне. Рекомендация — (б); до решения новые HEX не использовать.
- Ссылки — `--color-info`, не primary.
- StatusBadge: текст всегда `--color-text` на subtle-фоне (12% тона), цвет — только в точке/иконке.
- Индикатор фокуса и границы полей ≥ 3:1 к фону (`--color-border` `#E2E8F0` — декоративная граница;
  у полей ввода использовать границу темнее, например `--color-text-muted`, или полагаться на label + фон).

## 3. Статус — не только цветом

Каждый статус = цвет + иконка/форма + текст (`DESIGN_SYSTEM.md` → StatusBadge). На плане зала у плитки
стола — текст статуса, не только заливка. Таймер ожидания на KDS — число минут и иконка ⚠ при превышении,
а не только цвет рамки. Графики в отчётах — подписи значений/легенда с текстом.

## 4. Клавиатура и фокус

- Весь функционал доступен с клавиатуры; порядок Tab = визуальный порядок.
- Видимый фокус: `:focus-visible` — кольцо 2px `--color-info` с offset 2px (на KDS — 3px `--color-bg`).
- Skip-link «Перейти к содержимому» в admin/landing.
- Модальные окна: focus trap, Esc закрывает, фокус возвращается на триггер; первый фокус — первое поле или
  безопасная кнопка (в ConfirmDialog — «Отмена», не danger).
- DataTable: сортируемые заголовки — кнопки с `aria-sort`; меню действий — стрелки, Enter, Esc.
- Горячие клавиши (admin/cashier): `/` — поиск, `N` — новое (где применимо), `Enter` — подтвердить в форме
  оплаты. Не перехватывать сочетания браузера/скринридеров; список — в справке «?».
- Минимальная цель — 24×24px (WCAG 2.5.8), а по дизайн-системе для touch ≥ 44px.

## 5. Формы

- Видимый `<label>` у каждого поля (placeholder — не замена). Обязательность — `*` и `aria-required`.
- Ошибка — рядом с полем, `aria-invalid="true"` + `aria-describedby` на текст ошибки; при сабмите фокус
  переходит на первое поле с ошибкой; сводка ошибок вверху для длинных форм.
- Серверные ошибки валидации (`errors` в ProblemDetails) отображаются у соответствующих полей.
- Денежные/количественные поля: `inputmode="decimal"`, единица/валюта видимым текстом.
- Не ограничивать время на заполнение; при истечении сессии — тихий refresh, без потери введённого.

## 6. Динамические обновления (ARIA live)

- Toast-контейнер: `role="status"` + `aria-live="polite"` для success/info; ошибки — `role="alert"`
  (`aria-live="assertive"`). Не более одного объявления за событие.
- Индикатор связи (Онлайн/Переподключение/Нет связи) — `aria-live="polite"`.
- KDS: новые тикеты объявляются polite-регионом «Новое задание: стол 7, 2 позиции» + звук (отключаемый).
  Звук — не единственный сигнал: визуальная подсветка новой карточки 5 секунд.
- Обновление списков по realtime не должно сбрасывать фокус и позицию скролла пользователя.

## 7. KDS: читаемость на расстоянии

- Расстояние чтения 1.5–3 м: базовый текст ≥ 20px, позиции 22–24px bold, номер стола 28–32px.
- Тёмная тема с высоким контрастом, без тонких шрифтов (вес ≥ 500), без мелкого серого текста — вторичная
  информация `#F8FAFC` с opacity не ниже .75 (проверить ≥ 4.5:1).
- Кнопки статуса ≥ 56px высотой, на всю ширину карточки; подтверждение не нужно (есть recall).

## 8. Движение и медиа

- `prefers-reduced-motion: reduce` — отключить переходы, мигание новых карточек заменить статичной рамкой.
- Ничего не мигает чаще 3 раз в секунду. Автоскрытие toasts можно приостановить (hover/focus).
- Фото блюд — `alt` с названием блюда; без фото — плейсхолдер с `aria-hidden`.

## 9. Масштабирование

- Интерфейс работает при zoom 200% и ширине 320px CSS (reflow, WCAG 1.4.10) — кроме KDS, где допускается
  переход на одну колонку.
- Размеры шрифтов в `rem`; не запрещать масштабирование в `<meta viewport>`.

## 10. Чек-лист Definition of Done для UI

- [ ] Все строки через i18n, `lang` корректен
- [ ] Клавиатура: всё доступно, фокус видим, модалки ловят фокус
- [ ] Контраст текста ≥ 4.5:1 (крупного ≥ 3:1), статусы не только цветом
- [ ] Ошибки форм у полей, связаны через `aria-describedby`
- [ ] Toasts и realtime-обновления в live-регионах
- [ ] Проверено axe без critical/serious нарушений
