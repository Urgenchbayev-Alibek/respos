# Screen Inventory — 18 обязательных экранов (ТЗ §9.3)

Маршруты — **предложение**; источник истины — роутер `respos-admin` (`src/app/router/`).
Права — коды из `respos-contracts/PERMISSIONS.md`. Все branch-экраны отправляют `X-Branch-Id`.
Общие состояния для каждого экрана: loading (skeleton), empty, error (по `code` + retry), success (toast) —
см. `DESIGN_SYSTEM.md` §3. Ниже перечислены только специфичные состояния.
HTML-макеты: `assets/` (помечены ★).

---

## 1. Public landing
- **Приложение/маршрут:** `respos-landing` `/` (+ `/features`, `/pricing`, `/faq`, `/contacts`, `/privacy`, `/terms`)
- **Права:** публично. Форма → `POST /public/demo-requests` (honeypot `website`, rate limit).
- **Компоненты:** Hero, блок модулей, тарифы из `GET /public/plans` (информационно), FAQ, форма заявки, переключатель RU/UZ.
- **Состояния:** форма — отправка / успех «Мы свяжемся» / 429; юридические страницы — плашка «Черновик, требует юридической проверки».
```
[Logo]  Возможности  Тарифы  FAQ  Контакты      [RU|UZ] [Демо]
  Управляйте рестораном в одном окне          [ скриншот ]
  [Запросить демо]
  Столы · Заказы · Кухня · Склад · Касса · Отчёты
  Starter | Business | Enterprise   (информационно)
  Форма: Имя, Телефон, Ресторан, Город, Сообщение [Отправить]
```

## 2. Login
- **Маршрут:** `/login` (+ `/forgot-password`, `/reset-password`, `/accept-invitation`)
- **Права:** публично.
- **Компоненты:** Email, Password (показать/скрыть), «Забыли пароль?», язык RU/UZ.
- **Состояния:** неверные данные (без уточнения, что именно), 429 с таймером, заблокирован; forgot — всегда «Если аккаунт существует, мы отправили письмо».

## 4. Users & Roles
- **Маршрут:** `/admin/users`, `/admin/roles`
- **Права:** `users.read` (+ `users.create/update/deactivate`), `roles.read`/`roles.manage`.
- **Компоненты:** DataTable пользователей (фильтры статус/роль/филиал/поиск), модалка приглашения, редактор роли — матрица permissions по модулям (чекбоксы), системные роли — read-only с «Создать копию».
- **Состояния:** ссылка приглашения (dev/demo, кнопка «Скопировать»); нельзя деактивировать себя/последнего owner — disabled с подсказкой.

## 5. Branch settings
- **Маршрут:** `/admin/branches`, `/admin/branches/:id/settings`
- **Права:** `branches.read`/`branches.manage`, `settings.manage`.
- **Компоненты:** форма филиала (название, адрес, телефон, timezone), настройки: `serviceChargePercent`, `taxPercent`, `allowNegativeStock` (Switch + ConfirmDialog, аудит), `receiptFooter`, триггер списания (read-only «При оплате»).
- **Состояния:** 422 `plan.limit_exceeded` при создании филиала; несохранённые изменения — предупреждение при уходе.
```
Филиал «Центр»                         [Сохранить]
Название [____]  Телефон [____]  Часовой пояс [Asia/Tashkent▾]
Сервисный сбор [ 0 ]%   Налог сверху [ 0 ]%
[ ] Разрешить отрицательные остатки
Списание ингредиентов: При полной оплате (MVP)
```

## 8. Menu management
- **Маршрут:** `/admin/menu` (вкладки: Категории, Блюда, Модификаторы, Станции кухни `/admin/kitchen-stations`)
