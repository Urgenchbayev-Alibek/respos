# Responsive Rules

Mobile-first CSS. Один набор брейкпоинтов на всё приложение (константы в `src/shared/ui/breakpoints.ts`
и CSS custom media / media queries).

## Брейкпоинты

| Имя | Min width | Типичное устройство |
|---|---|---|
| `xs` | 0 | Телефон (360–414) |
| `sm` | 640px | Большой телефон, landscape |
| `md` | 768px | Планшет portrait |
| `lg` | 1024px | Планшет landscape, ноутбук |
| `xl` | 1280px | Desktop |
| `2xl` | 1536px | Большой монитор, TV для KDS |

## Целевые устройства по workspace

| Workspace | Основное | Также поддерживается | Ориентация |
|---|---|---|---|
| Admin Panel | Desktop `xl` | Ноутбук `lg`, планшет `md` (просмотр и простые правки), телефон — dashboard и списки | любая |
| Waiter | Планшет `md`–`lg` | Телефон `xs`–`sm` | portrait и landscape |
| KDS | Планшет landscape `lg`, TV `2xl` | — | **landscape**; в portrait — одна колонка + предупреждение «Поверните экран» не блокирующее |
| Cashier | Desktop `lg`–`xl` | Планшет `md` | landscape предпочтительно |
| Stock | Desktop `lg` | Планшет `md` (приёмка товара на складе) | любая |
| Platform | Desktop `xl` | Ноутбук `lg` | — |
| Landing | Все | — | — |

## Правила layout

1. **Никакого горизонтального скролла страницы** на любой ширине ≥ 360px. Допустим горизонтальный
   скролл только внутри: chips категорий, таблиц на `md`+ с явной тенью-подсказкой, таймлайна броней.
2. **Sidebar (admin/stock/platform):** `xl`+ — развёрнут 240px; `lg` — свёрнут 64px (иконки + tooltip);
   `< lg` — скрыт, открывается drawer по кнопке ☰ с оверлеем. Состояние свёрнутости запоминается.
3. **Шапка:** всегда видны филиал, индикатор связи (waiter/KDS/cashier), уведомления, профиль. На `xs` —
   переключатели языка и организации уходят в меню профиля.
4. **Таблицы → карточки:** на `< md` DataTable рендерит список карточек: заголовок (главное поле),
   StatusBadge справа, 2–3 ключевых поля, действия в kebab-меню. Фильтры — в выдвижной панели «Фильтры (N)».
5. **Формы:** одна колонка на `< md`, две на `lg`+. Футер с действиями — sticky снизу на mobile.
6. **Модальные окна:** на `< sm` — full-screen sheet; кнопки действий внизу во всю ширину.
7. **Dashboard:** сетка KPI — 1 колонка `xs`, 2 `sm`, 4 `lg`+. Списки под KPI — 1 колонка до `lg`, 2 на `lg`+.
8. **Waiter, экран заказа:**
   - `lg`+ (landscape планшет): split-view — меню 60–65% слева, чек 35–40% справа, кнопка «На кухню» закреплена внизу чека.
   - `md` portrait: меню сверху, чек — нижняя выдвижная панель с итогом и кнопкой (свёрнутая высота 72px).
   - `xs`–`sm`: меню на весь экран, плавающая панель «Чек · 3 поз · 98 000 [На кухню]»; чек — отдельный экран.
   - Плитки блюд: auto-fill, min 140px (`md`+) / 2 колонки (`xs`).
9. **Waiter, план зала:** плитки столов auto-fill min 96px; на `lg`+ при наличии `PosX/PosY` — свободное
   размещение, иначе сетка. Нижний tab bar на `< lg`, на `lg`+ — вкладки в шапке.
10. **KDS:** колонки статусов (Новые / В работе / Готово) на `lg`+; карточки внутри колонки в 1–2 столбца
    в зависимости от ширины (min 300px). На `< lg` — вкладки статусов вместо колонок. Шрифт не уменьшать
    ниже 20px ни на какой ширине; дальние экраны (`2xl`) — масштаб 1.25.
11. **Cashier:** `lg`+ — список заказов слева (320px) + оплата справа; `md` — список, затем оплата отдельным экраном
    с кнопкой «Назад».
12. **Отчёты:** графики растягиваются на 100% ширины контейнера, на `xs` — минимальная высота 200px, подписи
    осей сокращаются (дни недели, `10.11`).

## Touch и плотность

- `pointer: coarse` → кнопки `lg` (48px), строки списков ≥ 48px, расстояние между целями ≥ 8px.
- `pointer: fine` (admin desktop) → компактная плотность допустима (кнопки 36–40px, строки 44px).
- Hover-эффекты не несут информации (на touch их нет); tooltip дублируется по long-press или видимым текстом.
- Свайпы не единственный способ действия: каждое swipe-действие имеет кнопку.

## Тестирование

Проверять ширины 360, 768, 1024, 1280, 1920 и обе ориентации для waiter/KDS. Frontend-тесты responsive layouts
(ТЗ §16) — на уровне компонентов: переключение table↔cards, sidebar drawer (см. `docs/testing/TEST_PLAN.md`).
