## Концепция

RestaurantOS — рабочий инструмент смены, а не витрина. Интерфейс должен работать в шумном зале,
на кухне с жиром на пальцах и за кассой в час пик. Визуальный язык — спокойный нейтральный slate
с одним тёплым акцентом **saffron `#E85D2A`** (ассоциация с пловом и тандыром), который
используется только для главного действия на экране и активной навигации.

Одно React-приложение (`respos-admin`) с разными **рабочими пространствами** (workspace) — у каждого
свой layout, плотность и размер шрифта. Публичный сайт — отдельное приложение `respos-landing`.

## Принципы

1. **Скорость ежедневных операций важнее декора.** Частые действия — в 1–2 касания. Никаких
   анимаций, задерживающих работу. Горячие клавиши в admin/cashier.
2. **Минимум касаний.** Официант: стол → блюда (тап = +1) → «На кухню». Модификаторы — только если
   у блюда есть обязательные группы. Повар: одно касание по карточке = следующий статус.
3. **Ясность статусов.** Каждый статус имеет цвет, иконку и текст (никогда только цвет). Цветовая
   карта едина для всего продукта (`DESIGN_SYSTEM.md` → StatusBadge).
4. **Сервер — источник истины.** UI может показывать предварительный расчёт суммы, но отображает
   результат сервера. После переподключения SignalR — перезагрузка данных; индикатор связи виден
   всегда (KDS, waiter).
5. **Честность.** Демо-функции помечаются бейджами «Демо», «Не подключено», «Запланировано».
   Ручная оплата — «Ручная отметка (демо)». Пречек — «Не является фискальным чеком».
   Демо-данные (`Organization.IsDemo`) — постоянная плашка «Демо-данные» в шапке.
6. **Безопасные опасные операции.** Отмена заказа, возврат, списание, деактивация — через
   ConfirmDialog с причиной; кнопка danger, не primary.
7. **Права определяют UI, но не защищают.** Недоступные действия скрываются (UX), проверка — на backend.
8. **Двуязычность с первого дня.** RU и UZ (латиница); вёрстка рассчитана на +30% длины текста.
9. **Плотность по контексту.** Admin — плотные таблицы; waiter/KDS — крупные цели ≥ 44px (KDS ≥ 56px).

## Не входит в дизайн MVP

Офлайн-режим, кухонные принтеры, мобильные приложения, программа лояльности, разделение счёта по
позициям, доставка (см. `User-Todo.md` Q1, Q9, Q10, Q13).
