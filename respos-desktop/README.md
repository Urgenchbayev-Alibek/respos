# respos-desktop — RestaurantOS для Windows

Программа для Windows (`RestaurantOS.exe`), которая показывает то же веб-приложение, что и браузер
(`../respos-admin`: админка, официант, кухня, касса, склад), но как обычное окно: со своим ярлыком, тихой
печатью чеков на термопринтер, режимом киоска для экрана кухни и автозапуском.

Один установщик подходит любому ресторану: адрес сервера RestaurantOS вводится при первом запуске.
Сервер (backend) при этом не меняется и никак не настраивается под программу.

- Почему Electron и как это устроено: [ADR-0016](../docs/architecture/ADR/0016-desktop-electron-loopback-gateway.md)
- Техническое задание на оболочку и контракт `window.resposDesktop`: [DESIGN.md](./DESIGN.md)

## Как это работает

```
Electron main ──► LocalGateway (http://127.0.0.1:47615)
                    ├─ статика: собранный respos-admin (resources/web-dist), SPA fallback → index.html
                    └─ прокси → <адрес сервера>:  /api/*  /hubs/* (HTTP + WebSocket)  /files/*  /health/*
Окно (sandbox) загружает http://127.0.0.1:47615/
```

Для окна приложение и API — один адрес (origin), поэтому вход, cookie сессии, SignalR и картинки работают так же,
как в браузере. Шлюз слушает только `127.0.0.1` и отвечает только самому приложению (проверка `Host` и `Origin`).

| Папка | Что внутри |
|---|---|
| `src/gateway/` | шлюз: статика, потоковый прокси, WebSocket-туннель, проверка сервера (обычный Node, без Electron) |
| `src/main/` | окна, меню RU/UZ/EN, настройки, IPC, печать, киоск, автозапуск, правила безопасности |
| `src/preload/` | `app-preload` — только `window.resposDesktop`; `settings-preload` — только для окна подключения |
| `src/settings-ui/` | окно «Настройки подключения» (локальная страница, строгий CSP, RU / UZ / EN) |
| `src/shared/` | контракт IPC, схема настроек, нормализация адреса сервера |
| `tests/` | unit-тесты (Vitest, фейковый сервер) |
| `e2e/` | сценарии Playwright: dev-сборка (`_electron`) и упакованный exe (CDP) |
| `assets/` | `icon.ico` (16–256 px) и `icon.png` — из `respos-admin/public/pwa-512x512.png` (`npm run icon`) |
| `dist/`, `web-dist/`, `release/` | результаты сборки (в git не попадают) |

## Сборка

Нужны Windows 10/11 x64 и Node.js ≥ 22.12. Rust, Visual Studio и права администратора не нужны.

```bash
npm ci
npm run lint && npm run typecheck && npm test   # проверки и unit-тесты
npm run build        # main + preload + окно подключения → dist/
npm run build:web    # сборка ../respos-admin для оболочки → web-dist/
npm run dev          # собрать и запустить (без web-dist/ показывается страница-заглушка)
```

`npm run build:web` собирает веб-приложение с `VITE_DESKTOP=true`, `VITE_API_BASE_URL=/api/v1`,
`VITE_HUB_URL=/hubs/restaurant` (переменные задаются внутри скрипта — так их не портит Git Bash).
**Перед сборкой для ресторана задайте `VITE_LANDING_URL`** — адрес публичного сайта с QR-меню: он вшивается в
QR-коды столов и в ссылку на меню доставки. Без него скрипт предупреждает, а ссылки ведут на `http://localhost:5174`.

Electron скачивается при первом запуске (или явно: `node node_modules/electron/install.js`).
Оболочки, запущенные из редакторов на Electron (VS Code и т. п.), наследуют `ELECTRON_RUN_AS_NODE=1`;
`npm run dev` / `npm start` и тесты убирают её сами, а «голый» `electron .` в таком терминале приложение не запустит.

### Сборка установщика

```bash
# PowerShell:  $env:VITE_LANDING_URL = 'https://respos-landing.vercel.app'; npm run dist
VITE_LANDING_URL=https://respos-landing.vercel.app npm run dist
```

`npm run dist` = `build:web` + `build` + electron-builder. Результат в `release/`:

| Файл | Что это |
|---|---|
| `RestaurantOS-Setup-<версия>.exe` | установщик NSIS: «для текущего пользователя», без прав администратора, ярлыки на рабочем столе и в «Пуске» |
| `RestaurantOS-<версия>-portable.exe` | переносимая версия: один файл, запускается без установки |
| `win-unpacked/` | распакованная программа (её проверяет `npm run e2e:packaged`) |

`npm run pack` собирает только `release/win-unpacked/` (быстро, без установщика) — так же, как CI.
Полная сборка занимает около 10 минут (дольше всего сжимается portable-версия). Версия берётся из `package.json`. Иконку пересобирает `npm run icon` (из `respos-admin/public/pwa-512x512.png`;
картинку уменьшает Electron, отдельная библиотека не нужна).

**Ошибка winCodeSign «Cannot create symbolic link».** Старый набор инструментов подписи electron-builder
(`winCodeSign-2.6.0.7z`) содержит символические ссылки macOS, а Windows не даёт создавать ссылки без привилегии
(нужен запуск от администратора или «Режим разработчика»), и распаковка архива падает. Здесь это решено в
`electron-builder.yml` двумя независимыми способами:

1. `win.signExecutable: false` — подписи нет, поэтому набор для подписи не скачивается вообще; иконку и сведения
   о версии в exe записывает встроенный редактор ресурсов electron-builder (resedit, чистый JS);
2. `toolsets.winCodeSign: "1.1.0"` — когда появится сертификат и подпись включат, `signtool` возьмётся из нового
   набора: это обычные zip-архивы без символических ссылок.

Проверено на этой машине без прав администратора и без «Режима разработчика»: в кэш (`ELECTRON_BUILDER_CACHE`)
скачиваются только `7zip`, `nsis-3.0.4.1` и `nsis-resources-3.4.1`. Если ошибка всё же появится (например, после
смены версии electron-builder) — включите «Режим разработчика» в параметрах Windows или запустите сборку из
терминала администратора; кэш можно очистить, удалив папку `%LOCALAPPDATA%\electron-builder\Cache`.

Если на диске C: мало места, кэши и временные файлы можно увести на другой диск переменными `TEMP`, `TMP`,
`npm_config_cache`, `ELECTRON_CACHE`, `ELECTRON_BUILDER_CACHE`.

Команда, которой собрана версия 0.1.0 на машине разработки (Git Bash, без прав администратора; в PowerShell те же
переменные задаются через `$env:ИМЯ = 'значение'`):

```bash
cd respos-desktop
export TEMP='D:\tmp\desktop' TMP='D:\tmp\desktop' npm_config_cache='D:\tmp\npm-cache'
export ELECTRON_CACHE='D:\tmp\electron-cache' electron_config_cache='D:\tmp\electron-cache'
export ELECTRON_BUILDER_CACHE='D:\tmp\electron-builder-cache'
VITE_LANDING_URL=https://respos-landing.vercel.app npm run dist
```

Адреса API (`/api/v1`, `/hubs/restaurant`) в командной строке не задаются — их выставляет `scripts/build-web.mjs`
(Git Bash превратил бы `/api/v1` в путь `C:/Program Files/Git/api/v1`).

## Установка

- **Установщик.** Запустите `RestaurantOS-Setup-<версия>.exe`. Он ставит программу в
  `%LOCALAPPDATA%\Programs\RestaurantOS`, создаёт ярлыки и сразу запускает её. Права администратора не нужны.
  Обновление — запуск установщика новой версии поверх; настройки и сессия сохраняются. Удаление — через
  «Приложения» Windows (настройки пользователя при этом остаются).
- **Portable.** Скопируйте `RestaurantOS-<версия>-portable.exe` куда угодно и запустите. При **каждом** запуске
  файл распаковывается во временную папку (20–40 секунд, окно появляется после распаковки), а при выходе папка
  удаляется — для постоянной работы на кассе ставьте установщик. Настройки лежат там же, где у установленной версии.

Файл не подписан, поэтому Windows покажет предупреждение SmartScreen — см. «Устранение неполадок».

## Первый запуск

1. Откроется окно **«Настройки подключения»**. Введите адрес сервера RestaurantOS, например
   `http://192.168.1.10:5080` или `https://api.example.uz` (без `http://` подставится `http://`).
2. Нажмите **«Проверить соединение»** — программа запросит `<адрес>/health/ready` (до 5 секунд) и покажет результат.
3. Нажмите **«Сохранить»** — откроется обычный экран входа RestaurantOS.

Там же выбираются термопринтер, печать без диалога, режим киоска, автозапуск и язык окна (RU / UZ / EN).
Позже окно открывается из меню **Файл → Настройки подключения** или из меню пользователя в приложении.
Если при запуске сервер недоступен, окно откроется само, а программа продолжит работу, как только сервер ответит.
При смене адреса сервера сессия и локальные данные предыдущего сервера стираются.

Настройки: `%APPDATA%\RestaurantOS\settings.json` (адрес сервера, принтер, режимы, положение окна; секретов нет).
Журнал: `%APPDATA%\RestaurantOS\logs\main.log`.

## Печать

- **Чеки 80 мм** (пречек, Z-отчёт, тикет кухни). Если в настройках выбран термопринтер и включено «Печатать чеки
  без диалога», чек сразу уходит на этот принтер: страница 80 мм, высота — по длине чека, поля нулевые. Иначе
  открывается системный диалог печати.
- **Листы A4** (QR-коды столов, отчёты «PDF / печать») всегда идут через системный диалог и никогда — на чековый
  принтер.
- Если принтер не найден или печать не удалась, приложение само открывает обычный диалог печати.
- Экспорт отчётов в CSV / Excel сохраняется через стандартный диалог «Сохранить как».

Тихая печать проверена автотестами до момента передачи задания драйверу; на реальном термопринтере её нужно
проверить при внедрении (ширина бумаги и поля задаются в драйвере принтера).

## Режим киоска (экран кухни)

- Включается галочкой «Режим киоска» в настройках или ключом запуска: `RestaurantOS.exe --kiosk`.
- Окно занимает весь экран, меню скрыто. Выход из киоска до следующего запуска: **Ctrl+Shift+Q**.
- Для экрана кухни включите ещё «Запускать при входе в Windows»: после перезагрузки ПК программа стартует сама,
  а если сервер ещё не поднялся — дождётся его.

Другие клавиши: **F5** — перезагрузить страницу, **F11** — во весь экран.

## Тесты

```bash
npm test                 # unit: шлюз (статика, прокси, cookie, WebSocket, Host/Origin), настройки, печать, URL-правила
npm run smoke            # оболочка с фейковым сервером: окна, мост, меню, киоск, запрет навигации (сервер не нужен)
RESPOS_E2E_SERVER_URL=http://localhost:5081 npm run e2e            # + настоящий backend и настоящий web-dist
RESPOS_E2E_SERVER_URL=http://localhost:5081 npm run e2e:packaged   # упакованный exe из release/win-unpacked
```

- `e2e/app.e2e.ts` — полный сценарий с настоящим веб-приложением и backend: первый запуск, вход, дашборд без
  ошибок в консоли, SignalR через шлюз, перезагрузка страницы, печать, экспорт отчёта, запрет `window.open` и
  навигации, перезапуск программы, отключение и возвращение сервера. Нужен `npm run build:web`.
- `e2e/packaged.e2e.ts` — то же ядро на упакованной программе (пути в asar, `resources/web-dist`, preload, fuses,
  второй запуск, вход и сохранение сессии после перезапуска). Playwright `_electron` её запустить не может (fuse
  `--inspect` выключен), поэтому тест подключается к окнам через `--remote-debugging-port`. Portable-версию
  проверяет та же команда: `node scripts/e2e-packaged.mjs release/RestaurantOS-<версия>-portable.exe`.
- Тестовый backend (не трогает основную базу разработки) описан в DESIGN.md, раздел «Test backend for desktop work».
  Вход ограничен 5 попытками в минуту на e-mail — сценарии входят по одному разу.

Тестовые переменные окружения (пользователям не нужны; при работе с настоящими данными их задавать нельзя):

| Переменная | Действие |
|---|---|
| `RESPOS_DESKTOP_USER_DATA` | папка профиля вместо `%APPDATA%\RestaurantOS` (настройки, сессия, блокировка единственного экземпляра) |
| `RESPOS_DESKTOP_GATEWAY_PORT` | порт шлюза (`0` — любой свободный) |
| `RESPOS_DESKTOP_PRINT_CAPTURE` | файл, в который задания печати записываются (JSON, по строке на задание) вместо отправки на принтер или открытия диалога |

## Устранение неполадок

| Что видно | Что делать |
|---|---|
| **«Система Windows защитила ваш компьютер»** (SmartScreen) при запуске установщика или portable-версии | Файл не подписан сертификатом. Нажмите **«Подробнее» → «Выполнить в любом случае»**. Если файл скачан из интернета, можно заранее открыть «Свойства» файла и поставить галочку «Разблокировать». Предупреждение исчезнет после покупки сертификата подписи кода (см. `User-Todo.md`). |
| Антивирус блокирует или удаляет файл | Та же причина — нет подписи. Добавьте файл в исключения или соберите установщик сами из исходников. |
| «Сервер недоступен» в окне подключения | Проверьте, что сервер запущен и ПК в той же сети: откройте в браузере `<адрес>/health/ready` — должно быть `Healthy`. Проверьте порт и брандмауэр на сервере. |
| «Сертификат сервера не прошёл проверку» для `https://` | Сертификат сервера просрочен, выписан на другое имя или его центр сертификации не установлен в Windows. Установите корневой сертификат в «Доверенные корневые центры» или используйте корректный сертификат. Проверка сертификата не отключается. |
| После перезагрузки страницы появился экран входа, хотя сервер просто был недоступен | Сессия не потеряна: когда сервер вернётся, нажмите F5 (или войдите снова). |
| «Переподключение…» / «Нет связи с сервером» в приложении | Сервер или сеть недоступны; приложение само восстановит связь. Адрес сервера — Файл → Настройки подключения. |
| После запуска настройки темы / филиала сбросились | Порт `47615` был занят другой программой, шлюз взял случайный порт (в журнале: `port 47615 is unavailable`). Освободите порт и перезапустите программу. |
| Вместо приложения страница «Веб-приложение не собрано» | Запуск из исходников без `web-dist/`: выполните `npm run build:web`. |
| Чек печатается через диалог, а не сразу | В настройках не выбран принтер, не включена печать без диалога, или принтер переименован / отключён (в списке он помечен «не найден»). |
| Чек обрезан или с большими полями | Задайте в драйвере принтера бумагу 80 мм и нулевые поля. |
| Программа не открывается второй раз | Работает один экземпляр: второй запуск только показывает уже открытое окно. |
| Portable-версия долго не появляется после двойного щелчка | Она распаковывается при каждом запуске (20–40 секунд). Подождите и не запускайте её повторно; для ежедневной работы используйте установщик. |
| Нужно начать с чистого листа | Закройте программу и удалите папку `%APPDATA%\RestaurantOS` (настройки, сессия, журнал). |
| При сборке: `Cannot create symbolic link` (winCodeSign) | См. «Сборка установщика». |
| e2e: `Vitest failed to find the runner` / `reading 'config'` | Папка открыта с маленькой буквой диска (`d:...`). Запускайте из `D:...` (Vitest на Windows загружает себя дважды при разном регистре буквы диска). |
| При сборке: `npm run dev` ничего не открывает | В окружении задана `ELECTRON_RUN_AS_NODE` — запускайте через `npm run dev` / `npm start`, а не `electron .`. |

Для обращения в поддержку приложите `%APPDATA%\RestaurantOS\logs\main.log` (токенов, cookie и содержимого
запросов в журнале нет).

## Безопасность

- Окна: `contextIsolation`, `sandbox`, без Node.js в странице; наружу доступен только мост `window.resposDesktop`
  (`isDesktop`, `appVersion`, `openConnectionSettings()`, `print()`).
- IPC: фиксированный список каналов, проверка аргументов и отправителя.
- `window.open` запрещён (обычные http/https-ссылки открываются в системном браузере; адрес самого шлюза наружу не
  отдаётся), навигация за пределы приложения блокируется, разрешения (камера, геолокация и т. д.) запрещены.
- Шлюз: только `127.0.0.1`, проверка `Host` и `Origin`, CSP для страницы приложения, проверка сертификатов https.
- Fuses упакованной программы: RunAsNode, `NODE_OPTIONS` и `--inspect` выключены; проверка целостности asar,
  загрузка кода только из asar и шифрование cookie включены.

## Известные ограничения

- Нет подписи кода (SmartScreen) и нет автообновления — новая версия ставится установщиком поверх.
- Адрес лендинга для QR-кодов вшивается при сборке (`VITE_LANDING_URL`), в отличие от адреса сервера.
- Тихая печать и автозапуск не проверялись на реальном оборудовании ресторана.
- Только Windows x64.
- Тестовые переключатели (`RESPOS_DESKTOP_USER_DATA`, `RESPOS_DESKTOP_GATEWAY_PORT`, `RESPOS_DESKTOP_PRINT_CAPTURE`,
  `--remote-debugging-port`) в установленной программе работают только с ключом `--respos-e2e`. Полное решение —
  отдельная e2e-сборка с флагом времени компиляции — не сделано.
- Новый адрес сервера сохраняется только если сервер отвечает (`/health/ready`): настроить программу заранее,
  при выключенном сервере, нельзя.
- `web-dist` лежит рядом с `app.asar`, а не внутри: проверка целостности asar не покрывает файлы веб-приложения.
- Ответы сервера отдаются из того же origin, что и приложение, без добавочных `nosniff` / `CSP sandbox`
  (защита опирается на проверку загружаемых файлов на сервере).
- Адрес без схемы превращается в `http://` и для публичных хостов; предупреждения о незащищённом соединении нет.
- Если порт 47615 занят, выбирается случайный и не запоминается: при каждом запуске меняется origin, и
  настройки из `localStorage` (тема, филиал) теряются.
- Цвет окна до загрузки страницы всегда светлый (`#f8fafc`), даже при тёмной теме и на экране кухни.
- Язык оболочки (меню, окно подключения) задаётся только в окне подключения и не следует за языком веб-приложения.
- Запрос «Настройки подключения» в первые миллисекунды после закрытия этого окна теряется (нужно повторить).
