# User-Todo — вопросы и решения для владельца проекта

Здесь собраны вопросы, которые требуют вашего решения. Пока ответа нет, работа идёт по
**допущению (default)** — его можно поменять позже. Отметьте `[x]` и впишите ответ.

## A. Бизнес-правила (раздел 20 ТЗ)

- [ ] **Q1. Типы заказов.** Допущение: `dine_in` + базовый `takeaway`. Доставка — нет.
- [ ] **Q2. Несколько филиалов в пилоте?** Допущение: архитектура multi-branch, в пилоте 1 филиал.
- [ ] **Q3. Бронирования в MVP?** Допущение: да, базовые (с проверкой пересечений).
- [ ] **Q4. Способы оплаты.** Допущение: `cash`, `card` (ручная отметка), `other`. Payme/Click/Uzum — не подключены.
- [ ] **Q5. Местные платёжные провайдеры** (Payme, Click, Uzum, Humo/Uzcard-эквайринг)? Нужны договор и доступ к тестовой среде. Сейчас — `ManualPaymentProvider` с пометкой «Демо».
- [ ] **Q6. Онлайн-ККМ / фискализация** (soliq.uz, виртуальная касса)? Сейчас пречек с пометкой «Не является фискальным чеком». Нужна консультация местного специалиста.
- [ ] **Q7. Когда списывать ингредиенты?** Допущение: **при полной оплате заказа** (одно событие, идемпотентно).
- [ ] **Q8. Отрицательные остатки.** Допущение: ручные операции не могут увести остаток в минус (настройка филиала `AllowNegativeStock=false`). Автосписание при продаже **может** увести в минус (продажа уже состоялась) — создаётся уведомление и запись аудита. Подходит?
- [ ] **Q9. Кухонные принтеры?** Допущение: нет, только KDS-экран.
- [ ] **Q10. Офлайн-режим?** Допущение: нет (ТЗ исключает).
- [ ] **Q11. RU и UZ с первого релиза?** Допущение: да, оба (узбекский — латиница). Тексты UZ сделаны машинно/черново — **нужна вычитка носителем**.
- [ ] **Q12. Налог, сервисный сбор, скидки.** Допущение: настройки филиала `serviceChargePercent` (по умолчанию 0%) и `taxPercent` (0%, начисляется сверху). Скидка на заказ — сумма или процент, только с правом `orders.discount.apply` и причиной. Нужно уточнить: НДС уже входит в цены меню? Сервисный сбор 10–15%?
- [ ] **Q13. Разделение счёта / частичная оплата.** Допущение: частичная оплата есть (несколько платежей разными способами), разделение счёта по позициям — после MVP.
- [ ] **Q14. Ожидаемая нагрузка** (пользователей, заказов в день)? Допущение: до 30 сотрудников, до 500 заказов/день на филиал.

## B. Технические решения (можно оставить как есть)

- [ ] **T1. Версия .NET.** На машине установлены .NET 8 и 9 SDK; используется **.NET 8 LTS**. Важно: поддержка .NET 8 заканчивается 10.11.2026 → рекомендую установить **.NET 10 LTS SDK**, после этого смена `TargetFramework` на `net10.0` + обновление пакетов (≈1 час работы). Установить .NET 10?
- [ ] **T2. Авторизация.** Выбрано: короткий access JWT (в памяти браузера) + refresh token в httpOnly cookie с ротацией (ADR-0003).
- [ ] **T3. Хостинг backend + PostgreSQL** (раздел 11): нужно выбрать платформу (Render / Railway / Fly.io / Azure / VPS в UZ) и зарегистрировать аккаунты — это можете сделать только вы. Для реального ресторана рекомендую платный VPS/managed Postgres с бэкапами.
- [ ] **T4. Vercel** для `respos-admin` и `respos-landing`: нужен ваш аккаунт и подключение GitHub-репозитория. Конфиги (`vercel.json`) подготовлены.
- [ ] **T5. GitHub-репозиторий.** Локально создан git-репозиторий (без push). Создайте пустой репозиторий на GitHub и пришлите URL — тогда заработает CI (`.github/workflows`).
- [ ] **T6. Email (восстановление пароля, приглашения).** Сейчас заглушка (письмо пишется в лог, в Development — ссылка показывается админу). Какой SMTP/провайдер использовать?
- [ ] **T7. Название продукта и домен.** Рабочее «RestaurantOS», папка «ResPOS». Финальное название и домен?
- [ ] **T8. Мобильное приложение / Telegram-бот.** По ТЗ в MVP не входят (адаптивный веб). Нужны позже?
- [ ] **T9. Claude Design.** Отдельный дизайн-артефакт «RestaurantOS — Product Design» сделан в виде документов в `docs/design/`. Если хотите макеты в Claude Design — откройте его и попросите сгенерировать по `docs/design/DESIGN_BRIEF.md`.
